# Docs

Long-form reference written for people, meant to outlast whatever project first prompted it.

The rule shaping this domain is that nothing here may assume a particular application. Guidance written inside a client project dies with that project, even though most of what it explained was never client-specific. Pulling that material out and stripping the specifics is what this domain is for.

Two kinds of guide live here. One explains how to get to a working development environment and is tied to the toolchain versions this repository pins, so the guide, the pins, and the verification script are kept in agreement and move together. The other explains how a third-party system works well enough to make decisions about it, covering concepts and the tradeoffs between competing approaches rather than prescribing one path and narrating its steps.

The audience is a reader, not an agent. Documentation describing this repository to an agent lives elsewhere and is organized on different principles.
